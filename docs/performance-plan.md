# Performance issue implementation plan

This pass targets Windows, following the environment correction. Preserve gameplay authority in Elixir and meshing/presentation in Rust. Measure algorithm changes in the same build profile; compare profiles separately. Raw generated captures belong under ignored `.tools/` or `bench/results/` paths.

| Issue | Approach and order | Verification gate |
| --- | --- | --- |
| [#1](https://github.com/nahharris/wyram/issues/1) | This pass: plane masks and greedy rectangles, merged only within one material and face direction. Read interior neighbors directly from packed data. Retain the simple mesher as a test oracle. | Expand rectangles to oriented unit faces; exact coverage, winding and color parity for terrain, mixed materials, holes, seams, edits, negative coordinates and randomized chunks. Alternate benchmark order with warmup, raw timings and vertex/upload-byte counts; matched desktop routes. |
| [#6](https://github.com/nahharris/wyram/issues/6) | This pass: explicit optimized profile with symbols, shared launcher/staging, compiled profile metadata in captures. | Debug and optimized builds/tests; verify metadata, launcher selection and unchanged release packaging. Report profile effects separately from greedy effects. |
| [#5](https://github.com/nahharris/wyram/issues/5) | Implemented: dedicated bounded IPC writer; coalesce pending player poses, preserve edit order, end the session on edit saturation or connection failure. | Gated writer and real Windows delayed/closed pipe tests; matched slow-receiver admission benchmark and ordinary desktop routes. See the outbound design and performance results. |
| [#4](https://github.com/nahharris/wyram/issues/4) | Bounded asynchronous retrieval coordinated by ClientPort; prioritize nearby chunks and abandon obsolete view work. Region ownership stays unchanged. | Message responsiveness under generation load, revised edits and unload/reload parity, bounded in-flight work, actor queue delay and time-to-visible measurements. |
| [#3](https://github.com/nahharris/wyram/issues/3) | Versioned binary batches, background decoding and bounded per-frame intake. Coordinate with asynchronous streaming. | Malformed/oversized/truncated packet tests, protocol parity, backpressure and revision ordering; transport volume, decoding time and frame tails. |
| [#2](https://github.com/nahharris/wyram/issues/2) | Capacity-managed GPU buffers and reusable staging; split oversized uploads without exposing partial meshes. Reassess after greedy geometry reductions. | GPU resource lifetime/unload tests, bounded allocations, correct old-mesh replacement, upload CPU and GPU timing. Budget admission is not a driver time guarantee. |
| [#8](https://github.com/nahharris/wyram/issues/8) | Build on this pass's captures: automated control routes, startup/steady segmentation, metadata and supported GPU timestamp queries. | Repeated matched cold/warm routes, dropped-sample reporting and schema smoke tests. Do not impose hardware-dependent CI performance thresholds. |
| [#7](https://github.com/nahharris/wyram/issues/7) | Experimental GPU mesher after CPU/buffer/transport evidence identifies remaining cost. Require capability fallback and overflow handling. | Geometry parity, bounded memory, no frame-thread readback, hardware comparison including GPU contention; adoption depends on measured benefit. |

Commit and push only after local checks, tests, source review and measurement. Keep Windows CI green. Full-game improvement remains inconclusive when route noise or other phases dominate, even if geometry/worker measurements improve.
